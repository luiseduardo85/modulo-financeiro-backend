# Persistence

Official database: PostgreSQL. Schema evolution: Flyway. Hibernate uses
`ddl-auto=validate`.

## Naming

Tables, columns, constraints, and indexes use camelCase. Examples:
`"contaFinanceira"`, `"empresaId"`, and `"dataVencimento"`.

Do not use snake_case. PostgreSQL identifiers containing uppercase characters
must be quoted.

The Hibernate physical naming strategy is
`org.hibernate.boot.model.naming.PhysicalNamingStrategyStandardImpl`. This
prevents Spring Boot's default strategy from converting camelCase identifiers
to snake_case.

Global identifier quoting is not enabled. Every mixed-case PostgreSQL identifier
must be explicitly quoted in the JPA mapping using Hibernate backticks:

```java
@Table(name = "`contaFinanceira`")
@Column(name = "`empresaId`")
```

The corresponding Flyway identifiers use PostgreSQL double quotes:

```sql
"contaFinanceira"
"empresaId"
```

The first real entity and migration must include a PostgreSQL integration test
that proves the explicit quoted camelCase mapping. TECH-007 has no mapped entity,
so `ddl-auto=validate` currently proves safe JPA initialization but has no
business table or column metadata to compare.

## Schema ownership

- `spring.jpa.open-in-view=false` keeps persistence access out of REST rendering.
- `spring.jpa.generate-ddl=false` prevents portable JPA schema generation.
- `spring.jpa.hibernate.ddl-auto=validate` only validates mapped entities.
- Flyway is the only mechanism allowed to create or alter the schema.
- Hibernate must never use `update`, `create`, or `create-drop`.

## Mapping conventions

### Identifiers

- Java type: `Long`.
- PostgreSQL type: `BIGINT GENERATED BY DEFAULT AS IDENTITY`.
- JPA generation strategy: `GenerationType.IDENTITY`.
- Do not introduce a generic ID type or UUID default without a later decision.

### Enums

- Persist as PostgreSQL `VARCHAR`.
- Map with `@Enumerated(EnumType.STRING)`.
- Never use `EnumType.ORDINAL` or a PostgreSQL native enum by default.

### Money and time

- Money: Java `BigDecimal`, PostgreSQL `NUMERIC(19,2)`, and explicit JPA
  `precision = 19, scale = 2`.
- Business dates: Java `LocalDate`, PostgreSQL `DATE`.
- Technical and event timestamps: Java `Instant`, PostgreSQL `TIMESTAMPTZ`.
- Booleans: Java `Boolean`/`boolean`, PostgreSQL `BOOLEAN`.
- Avoid `float` and `double` for money and `LocalDateTime` for global instants.

### Columns and relationships

- Declare physical table, column, and join-column names explicitly.
- Keep JPA nullability consistent with Flyway `NULL` and `NOT NULL` constraints.
- Declare to-one relationships with `FetchType.LAZY`.
- Add cascades only for documented aggregate ownership.
- Do not use broad `CascadeType.ALL` or cascade deletes by convenience.

## Domain and persistence separation

- Domain classes contain no JPA, Hibernate, Spring Data, or database annotations.
- JPA entities and Spring Data repositories belong to Infrastructure.
- Domain or Application repository ports expose use-case-oriented operations and
  never extend `JpaRepository`, `CrudRepository`, or another Spring Data type.
- Infrastructure adapters implement those ports and map explicitly between the
  domain and persistence models.
- Do not introduce generic repository, mapper, or CRUD abstractions.
- Transaction boundaries remain in Application use cases.

## Optimistic locking

- Add `@Version` only to an Infrastructure JPA entity whose documented operations
  require concurrent-update protection.
- Map it explicitly to a non-null quoted `"version"` `BIGINT` column from Flyway.
- Do not place `@Version` in Domain or a generic base class.
- Translate an actual optimistic-lock failure at the appropriate outer boundary;
  persistence exception translation is deferred until a real repository exists.

## Technical audit fields

- When required, declare `createdAt` and `updatedAt` explicitly on each JPA entity.
- Use Java `Instant` and PostgreSQL `TIMESTAMPTZ` with matching nullability.
- Do not introduce `BaseEntity` or a speculative `@MappedSuperclass`.
- Do not add `createdBy`, `updatedBy`, `AuditorAware`, or user-based auditing until
  the external authentication contract exists.
- Introduce the timestamp population mechanism with the first real entity so it
  can be tested against its documented lifecycle.

## Additional rules

- Avoid cascade delete in financial data unless explicitly documented.
- A draft may be deleted only where the documented business rules allow it.
- Company-scoped queries include company context where applicable.
- Use optimistic locking for documented concurrent operations.
